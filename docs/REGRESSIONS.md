# Registre des régressions

Ce fichier répond à une question simple : **ce bug peut-il revenir sans que personne ne le voie ?**
Il recense les vrais bugs corrigés, ce qui les protège aujourd'hui, et ce qui reste à contrôler à la main avant une release.
Il ne remplace ni `CHANGELOG.md`, qui dit ce qui a changé, ni `docs/FEATURES.md`, qui décrit ce que FriRSS sait faire.
La méthode de test, elle, est décrite dans `docs/TESTING.md`.

Le registre n'est pas exhaustif : il retient les bugs qui ont touché l'utilisateur, ou qui auraient pu perdre des données ou ouvrir une faille.

## Règle de tenue

1. **Chaque bug corrigé ajoute sa ligne dans le même commit que son correctif**, avec sa protection.
2. **Une ligne ne se supprime pas.** Son état et sa protection évoluent ; son identifiant reste.
3. **Le numéro suivant est le plus haut numéro + 1**, et la ligne va en tête du registre.
4. **Une protection se cite par son titre exact**, sans raccourci. Si un test est renommé, la ligne suit.
5. **`Couvert` se prouve en lisant le corps du test**, jamais d'après son titre : l'assertion doit échouer si le correctif disparaît. Dans le doute, écrire `À vérifier`.

## États

| État | Sens |
|---|---|
| `Couvert` | Un test automatisé, lu, vérifie directement le symptôme. |
| `Manuel` | Seul un appareil ou un service réel peut le vérifier : voir la checklist. |
| `Non couvert` | Recherché, rien ne protège ce bug. |
| `À vérifier` | Un test existe, mais rien ne confirme qu'il attraperait le bug. |

Pour compter une catégorie :

```bash
grep -c '| Non couvert |$' docs/REGRESSIONS.md
```

## Niveaux de protection

- **Vitest** : `fichier › titre complet`, tel que l'affiche `npx vitest run`.
- **CI** : étape nommée de `.github/workflows/ci.yml` ou de `security.yml`.
- **Banc** : tests de bout en bout contre un vrai FreshRSS, dans un environnement privé isolé. Ses sources ne sont pas dans ce dépôt.
  - `N1` : contrôles de la CI sur le conteneur durci, avec Redis.
  - `N2 contrat` : ce que FreshRSS répond réellement. `N2 application` : ce que FriRSS lui envoie.
  - `N3` : parcours dans un vrai navigateur.
- **Réintroduit et détecté par le banc** : le bug a été remis volontairement, et le banc a échoué. C'est la preuve la plus forte du registre.

## Checklist manuelle avant release

Pour ce qu'aucun automate ne couvre. À dérouler sur l'instance de test, après avoir lu l'étiquette de version en bas de la barre latérale. Compter dix minutes.

**iPhone, app installée**

- [ ] Appui long sur un article, lever le doigt, choisir une action : le menu reste ouvert (REG-030).
- [ ] Ouvrir les Préférences, toucher la croix : le panneau se ferme (REG-029).
- [ ] Ouvrir le menu d'un flux dans le tiroir : il tient entier à l'écran (REG-035).
- [ ] Exporter une sauvegarde : le fichier arrive (ce chemin n'a jamais été confirmé sur iOS).

**iPad, app installée**

- [ ] Tourner l'écran avec un article ouvert : la mise en page suit, rien n'est coupé.
- [ ] Ouvrir puis fermer un menu et les Préférences au doigt.

**Safari sur Mac**

- [ ] Se connecter, ouvrir un article avec images, recharger : les images s'affichent, aucune erreur (REG-014).
- [ ] Lancer une recherche au clavier : elle se soumet et filtre (REG-031).

**Connexion SSO réelle (Authentik), Mac et iPhone**

- [ ] Se connecter jusqu'au retour dans FriRSS, sans message d'erreur (REG-039, REG-040).

**Android, app installée**

- [ ] Atteindre le bas d'une longue liste : le dernier article est visible (REG-036).
- [ ] Geste retour depuis un article, le tiroir et les Préférences : on remonte d'un niveau sans quitter l'app (REG-037).

**Instance de test, après déploiement**

- [ ] Recharger deux fois : le service worker sert le nouveau bundle et l'étiquette de version est la bonne.
- [ ] Marquer un article lu, changer de flux, revenir : il reste lu.
- [ ] Ouvrir un flux à images : elles s'affichent (REG-014).
